Pay-on-Proof

Outcome-based payments on Cardano: money moves only when signed real-world data (API3) proves a condition agreed in advance. One contract, any data source, nobody in the middle.

What this is, in one minute

The problem

A buyer and a seller, often two software agents, do not trust each other. Paying first risks losing the money. Paying after delivery risks never being paid. A platform in the middle ends up as the judge.

The idea

The buyer's payment goes into a smart contract with the rule written in it: pay the seller if signed data proves the outcome before a deadline, otherwise refund the buyer.

Why it holds

The data comes from an AirnodeHub (API3) provider that signs its answer. The contract checks the signature, the question asked, how old the answer is and the value. Nobody can redirect the money.

How a payment moves

  1. The buyer's agent asks for an escrow ("pay the creator if the post reaches 300,000 likes before 14:00") and the service answers with a price and the exact policy. The buyer's client recomputes that policy itself and pays only if it matches field by field.
  2. The payment lands in the contract. With Cardano's x402 "script" transfer method the payment output goes straight to our validator with the policy as its datum. No one holds it in between.
  3. A signed answer is the proof. The data provider signs "the post has 308,791 likes" (or the rainfall total, or any numbers an AirnodeHub source returns). The contract rebuilds the signed text, checks the signature, the question, the age and, for feeds that sign one, when the value was observed.
  4. The seller's keeper collects. It finds policies that pay the seller, fetches the signed answer, and submits the release. Anyone could; the money can only go to the seller named in the policy.
  5. Or the buyer is refunded. After the deadline only the buyer's key can take the money back, and not before.

What it does not prove

  • A signature proves what the data provider returned, not that it is true. Likes can be bought; an API can be wrong.
  • It settles outcomes that data can verify: pay for the result, not for the effort. It does not judge the quality of an agent's work.
  • There is no dispute process: if the data says the condition holds, the seller is paid.
  • The observation time of a value is checked only for feeds that sign one (the free price feed we use as a test fixture). Rainfall and tweets sign none.
  • Testnet only, not audited.
